# Управляемый Price Book — локальная версия

Работа выполнялась только в локальном проекте. Мобильная версия не входит в текущую задачу; основной интерфейс проверен в Chrome на десктопе.

## Как пользоваться

1. Откройте **Прайс-лист / Price book**. Семь исходных категорий сохранены, у каждой есть тематическая Lucide-иконка.
2. **Добавить категорию** создаёт раздел справочника. Задайте обязательное английское название, при желании русский перевод. Нажмите иконку, чтобы открыть библиотеку из 75 тематических значков с поиском EN/RU. Поля описаний категории и выпадающий список заменены компактным выбором иконки; ранее сохранённые описания остаются в данных. Карандаш возле заголовка позволяет переименовать категорию. Переименование исходной категории не меняет идентификатор формулы.
3. **Добавить позицию** создаёт работу, материал или услугу. Можно выбрать SF, LF, штуки, часы или фиксированную единицу, указать количество по умолчанию, цену, описания и характеристики.
4. Способы цены: **количество × ставка**, **фиксированная сумма** (количество всегда 1), **цена требует уточнения**. Последний вариант не подставляет выдуманную цену и не включён в подтверждённую числовую сумму.
5. В исходных категориях вкладка **Ставки и параметры** редактирует действующие правила, а **Позиции для смет** содержит новые самостоятельные позиции. У пользовательской категории сразу открыт список позиций.
6. Изменения ставок применяются кнопкой **Сохранить ставки**. Категории и позиции сохраняются собственными кнопками в формах сразу в базу данных. Повторное открытие страницы и перезапуск приложения сохраняют данные.
7. В смете: **Добавить позиции → Прайс-лист → выбрать позицию → количество → Добавить позицию в зону**. Доступны активные позиции из всех активных категорий, включая новые работы, материалы и услуги.
8. Архивирование требует подтверждения. **Показывать архив** позволяет найти и восстановить запись. Архив категории скрывает её позиции при выборе для новых смет. Уже добавленные строки смет остаются.

В смету копируются английские название, описание, категория и характеристики, а также текущая цена. Последующее переименование, изменение цены или архивирование справочника не изменяет ранее сохранённую смету. Язык EN/RU влияет на интерфейс; презентации продолжают использовать английские данные.

## Какие расчёты сохранены

- **Wall Panels, Cabinetry, Mirror** используют прежний `rule_engine.py` и исходные параметры. Новая категория не появляется в списке автоматических калькуляторов сама по себе.
- Для нового автоматического вида требуется отдельная формула: обработчик в `calculator_registry.py`, валидируемая модель запроса и маршрут API, форма ввода и контрольные примеры. Пользовательские характеристики — текстовые данные, а не выполняемые формулы.
- **Quick Estimate** сохраняет прежние отдельные формулы. Исторический разрыв между некоторыми настройками `quick_estimate` и шаблонами помещений не объединён автоматически; в интерфейсе есть пояснение. Новая позиция материала не становится автоматически надбавкой стенового калькулятора.
- Исходные ставки, модели смет и генераторы PDF/XLSX не переписаны. Роли доступа не добавлены; действует прежняя авторизация.

## Хранение и защита изменений

Каталог хранится в существующем JSON `pricing_config` под ключом `_catalog_v1`. Миграция схемы не нужна. Обновления каталога и ставок сериализуются блокировкой транзакции PostgreSQL. Версии записей и ревизия ставок предотвращают перезапись устаревшей формой. Сохранение ставок и сброс базовых цен сохраняют актуальный каталог независимо от его старой копии в открытом окне.

## Проверка

- Сборка frontend и TypeScript, 32 теста backend, 27 контрольных примеров Quick Estimate, EN/RU-проверки включая вложенные компоненты, проверка связи preview/download PDF и 45 неизменённых reference-файлов проходят.
- В Chrome созданы категория и позиция; проверены редактирование после перезапуска, переименование, архивирование и восстановление, все семь исходных категорий на EN/RU, длинные названия, формы и выпадающие списки.
- Через локальный API проверены цена за единицу, фиксированная цена, неподтверждённая цена, устаревшие версии, сохранение/сброс ставок без потери каталога, отсутствие изменений старых смет и три контрольных расчёта: $6,000 / $2,400 / $2,600.
- Через Builder добавлена работа: 3 SF × $16 = $48. Ранее сохранённый материал остался $125 после изменения его каталожной цены на $150.
- Тестовая категория `QA — Custom Finishes (verified)` перенесена в архив, отдельная QA-смета — в корзину. Они не смешиваются с обычными активными данными.
- Презентации не скачивались; PDF/XLSX проверялись существующими автоматическими тестами.

## Backup и откат

Резервная копия до изменений: `.local/backups/pricebook-20261025T151954/`. Содержит исходники, SHA-256, исходные строки `pricing_config`, полный локальный PostgreSQL dump. `change-files.json` ограничивает откат файлами этой задачи.

Из корня проекта, сначала просмотреть план:

```sh
.venv/bin/python scripts/pricebook_backup.py --restore-pricing .local/backups/pricebook-20261025T151954
.venv/bin/python scripts/pricebook_backup.py --restore-source .local/backups/pricebook-20261025T151954
```

Для исполнения добавить `--apply`. Откат справочника возвращает старые ставки и каталог, не затрагивая сметы и фотографии. Откат исходников выполнять после `npm run stop`, затем `npm run build` и `npm run dev`. Полный dump оставлен для аварийного восстановления в отдельную локальную базу; автоматически на рабочую базу он не накатывается. Кластер PostgreSQL не останавливать: он может использоваться другими локальными проектами.
