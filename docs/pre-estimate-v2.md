# Pre-Estimate V2 — локальный дизайн и откат

Обновлён только внешний вид Pre-Estimate и размещение его содержимого. V2 включён
локально. Excel, Final PDF, модели, расчёты, Price Book и данные BHUPESH не менялись.

## Открыть и скачать самостоятельно

http://localhost:5190/estimates/6e7ecce2-2475-4562-82a7-dddbf2144a64

В Summary нажать **Preview Pre-Estimate**, затем **Download Pre-Estimate PDF**.
В Builder выбрать режим Pre-estimate. Режим Final открывает текущий Final PDF;
Preview и Download каждого режима используют один файл. При обновлении дизайна закрыть прежний Preview
и открыть заново: PDF генерируется по текущему флагу, без сохранения в Estimate.

По последней просьбе пользователя скачивание через сайт/API не выполнялось.
BHUPESH V2 проверен локально в памяти; итоговый PDF-файл не сохранялся. Готовый V2
будет создан при нажатии пользователем Preview/Download. Старые PDF в output/pdf
относятся к прежней версии и не были перезаписаны.

## Почему повторялся чертёж

В базе к каждой из пяти зон действительно привязан одинаковый пользовательский PNG.
Это было сделано по предыдущей просьбе использовать один пример везде. Старый renderer
брал фотографии зоны, а не автоматически подставлял первую фотографию проекта.

Связи и файлы в базе оставлены без изменений. В V2 одинаковые файлы распознаются по
SHA256; общий reference выводится один раз в начале документа, а соответствующие зоны
получают подпись о расположении общего плана. При необычно длинном клиентском имени
reference получает самостоятельный слайд после обложки. Уникальное фото зоны выводится
только в этой зоне. Зона без фото не получает чужую фотографию.

Contain обязателен: исходные пиксели не обрезаются, пропорции сохраняются, никакого
cover/crop. Portrait получает узкую вертикальную область, wide drawing — более широкую
левую колонку, extreme panorama — горизонтальную композицию. Для 2–4 изображений
выбирается композиция по площади видимого содержимого. EXIF учитывается. Low-resolution
не получает искусственной детализации. Без фото текст использует полезную ширину.

## Переключить / откатить

Из корня проекта:

```zsh
python3 scripts/pre_estimate_design.py v1
npm run stop
npm run dev
```

Вернуться к V2:

```zsh
python3 scripts/pre_estimate_design.py v2
npm run stop
npm run dev
```

Либо поменять только `PRE_ESTIMATE_DESIGN=v1` / `v2` в `.env` и перезапустить приложение.
Откат не требует операций с базой данных. API URL, авторизация и имя скачивания прежние.
Ответ preview содержит X-Pre-Estimate-Design для диагностики. Final PDF не переключается.

До редизайна сохранён локальный snapshot:
`.local/backups/pre-estimate-v1-20261022T192418/`.
В нём прежний renderer, API route, config, .env, .env.example и manifest SHA256.
Для обычного отката достаточно флага, восстановление всего snapshot не нужно.

## Единая логика Pre-Estimate — 25 октября 2026

Все проекты используют общий `pre_estimate_service` и активный V2. Старые
`POST /pdf/{id}/generate` и `GET /pdf/{id}/download` для типа `pre` теперь тоже
вызывают этот renderer, как Preview/Download в Builder. Содержимое PDF при
неизменном снимке данных детерминировано. Ключ frontend-кеша обновлён для Pre.

Повторяющаяся обычная фотография остаётся в каждой зоне, куда её добавил
пользователь. В общий референс на обложке выносятся только повторяющиеся чертежи.
Это устраняет неожиданное исчезновение фотографий из зон тестового проекта.
Единственная общая секция `Project components` оформляется так же, как `General`;
настоящие именованные разделы и несколько групп сохраняют заголовки.

В созданной агентом QA-смете длинные технические описания происхождения ставок
перенесены без потерь в её `notes`. Вместо них — короткие `QA sample` / `QA demo
rate`. Названия работ, количество, цены, суммы, фото и секции не менялись.
Residence — контрольный образец: JSON и содержимое всех 13 PDF-страниц совпадают
с версией до исправления. QA содержит 61 позицию против 31 в Residence, поэтому
его 22 страницы (раньше 32) закономерно включают продолжения. Не используется
никакой выбор шаблона по ID или названию проекта.

Final PDF побайтно совпал с контрольной версией до этой задачи; его renderer,
титулка и корпоративный блок не менялись. Все ставки и Excel-генератор сохранены.

Контрольные файлы и результаты: `.local/qa/pre-unified/`. Исходный JSON QA до
переноса описаний: `qa-before.json`; он сохраняет все оригинальные поля.
Рабочая версия и локальный dump до изменений:
`.local/backups/pricebook-20261025T223857/`. `change-files.json` позволяет откатить
только source через `scripts/pricebook_backup.py --restore-source` (сначала dry
run). Не следует восстанавливать всю базу поверх более поздних пользовательских
правок; для отката данных QA достаточно восстановить только её descriptions и
notes из сохранённого JSON.
